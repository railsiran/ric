# `ric rails` — اجرای هر دستور Rails داخل کانتینر

`ric rails -- <command>` دستور `bin/rails <command>` را داخل کانتینر پروژه اجرا می‌کند، با stdin/stdout/stderr وصل به ترمینال شما. بعد از پایان کار، نتیجه از کانتینر به میزبان برگردانده می‌شود تا فایل‌های جدید (generatorها، migrationها و …) را بلافاصله در ادیتورتان ببینید.

## نحوه‌ی استفاده

```bash
ric rails -- generate model Post title:string body:text
ric rails -- db:migrate
ric rails -- db:rollback
ric rails -- routes
ric rails -- runner "puts User.count"
```

از داخل پوشه‌ی پروژه اجرا کنید.

علامت `--` در وسط، flagهای خود `ric` را از آرگومان‌هایی که به `rails` پاس می‌شوند جدا می‌کند. هر چیزی بعد از `--` بیاید، عینا منتقل می‌شود.

## کاری که انجام می‌دهد

۱. بررسی می‌کند کانتینر `<name>` در حال اجراست.
۲. `docker exec -w /workspace/<name> <name> bin/rails <args شما>` را با stdin/stdout/stderr متصل اجرا می‌کند.
۳. بعد از پایان دستور، هر چیزی در پوشه‌ی پروژه‌ی میزبان را پاک می‌کند (با حفظ `.git/` در صورت وجود) و کل درخت `/workspace/<name>` از کانتینر را دوباره کپی می‌کند.

ویژگی اصلی همان مرحله‌ی آخر است: هر چیزی که دستور Rails تولید کرده (فایل‌های مدل جدید، کنترلرها، migrationها، به‌روزرسانی‌های schema.rb) بدون نیاز به اجرای دستی `ric sync --reverse` به میزبان می‌رسد.

## کاربردهای رایج

- **Generatorها.** `ric rails -- generate scaffold Post title body:text` — migration، مدل، کنترلر، ویوها و تست‌ها را می‌سازد و بلافاصله در ادیتور می‌بینید.
- **Migrationها.** `ric rails -- db:migrate`، `ric rails -- db:rollback`، `ric rails -- db:seed`.
- **Routes و بازرسی.** `ric rails -- routes` برای جدول کامل routes.
- **اسکریپت‌های سریع.** `ric rails -- runner "puts User.count"` برای اجرای یک قطعه‌ی Ruby در محیط اپلیکیشن شما.

## تفاوت با `ric console`

| | `ric console` | `ric rails -- …` |
|---|---|---|
| REPL تعاملی | بله | خیر |
| دستور یک‌باره | خیر | بله |
| بازگشت خودکار به میزبان | کاربرد ندارد | بله |
| مناسب برای | کاوش | generatorها، migrationها، تسک‌های اسکریپتی |

## نکات احتیاطی

- پوشه‌ی پروژه‌ی میزبان در هر اجرا بازنویسی می‌شود. اگر تغییرات stage نشده‌ای دارید که در همان session هم داخل کانتینر نوشته بودید، برای `.git/` نسخه‌ی میزبان برنده است و برای بقیه‌ی فایل‌ها نسخه‌ی کانتینر.
- در دستورهایی که از طریق runner داده‌ای به `storage/` می‌نویسند مراقب باشید — این کار درست است، اما باید بدانید فایل اول وارد فایل‌سیستم کانتینر می‌شود و سپس به میزبان کپی می‌شود.

# `ric mcp` — Model Context Protocol server

`ric mcp` exposes ric's command surface as a Model Context Protocol server, so AI assistants like Claude can drive ric on your behalf — creating projects, syncing, running migrations, deploying — without you having to copy/paste commands into a terminal.

## Usage

```bash
ric mcp
```

This starts a JSON-RPC server on stdin/stdout following the MCP spec. You don't normally run it directly — you configure your AI assistant to launch it.

## What's exposed

The server advertises these tools:

| Tool | What it does |
|------|--------------|
| `ric_version` | Show the ric CLI version and build info |
| `ric_sync` | Sync host files into the container (`tmp/` and `storage/` excluded) |
| `ric_rails` | Run a `bin/rails` command inside the container and sync results back |
| `ric_container_start` | Start the project's container |
| `ric_container_stop` | Stop the project's container |
| `ric_migrate` | Run database migrations inside the container |
| `ric_deploy` | First-time deploy to the remote server (requires `.ric/deploy.yml`) |
| `ric_upgrade` | Upgrade an existing deployment, preserving DB and credentials |

Each tool runs in the project's current working directory — same way you'd run `ric` from the terminal.

## Configure Claude Desktop / Claude Code

In your Claude configuration (Claude Desktop's `claude_desktop_config.json` or Claude Code's `~/.claude/settings.json`), add:

```json
{
  "mcpServers": {
    "ric": {
      "command": "ric",
      "args": ["mcp"],
      "cwd": "/absolute/path/to/your/project"
    }
  }
}
```

`cwd` matters: ric commands assume they're run from inside a project directory.

If you switch projects often, you can either configure multiple entries (`ric-shop`, `ric-blog`) or omit `cwd` and let the assistant call `ric` from whichever directory the AI's tools think is current.

## A typical session

> **You:** "Add a Post model with title and body, run the migration, and tell me how many posts exist."
>
> **Claude (via ric_rails):** Generates the model, runs the migration, runs a `runner` to count posts, replies with the count.
>
> **You:** "Ship it."
>
> **Claude (via ric_upgrade):** Builds, uploads, migrates, restarts the app on your server.

## Safety notes

- `ric_deploy` and `ric_upgrade` make real changes on a real server. Make sure the assistant has explicit instructions about which projects/hosts it may touch.
- Master keys generated by ric are written to `.ric/keys/production.key` on your local machine; the MCP server doesn't transmit them anywhere — it's still local file access.
- The MCP server runs as **you** — same filesystem permissions, same SSH credentials. There's no sandbox.
